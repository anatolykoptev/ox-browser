# ox-browser v0.1.0 Design — Core MVP

**Date:** 2026-03-04
**Status:** Draft
**Goal:** Fetch pages, parse DOM, extract data. No JS. Usable as library and CLI.

## 1. Workspace Setup

**Problem:** Need a clean Rust workspace with 6 crates that compile independently.

**Design:** Cargo workspace with path dependencies. Each crate has single responsibility.

```toml
# Cargo.toml (root)
[workspace]
resolver = "2"
members = [
    "crates/core",
    "crates/http",
    "crates/js",
    "crates/security",
    "crates/crawler",
    "crates/mcp",
]

[workspace.package]
version = "0.1.0"
edition = "2021"
license = "MIT"
repository = "https://github.com/anatolykoptev/ox-browser"

[workspace.dependencies]
tokio = { version = "1", features = ["full"] }
anyhow = "1"
thiserror = "2"
tracing = "0.1"
```

Phase 1 only implements `ox-http` and `ox-core`. Other crates get stub `lib.rs`.

## 2. HTTP Client (`crates/http`)

**Problem:** Need async HTTP with cookies, proxy, custom headers, redirect following.

**Design:**

```rust
pub struct HttpClient {
    inner: reqwest::Client,
    cookies: Arc<cookie_store::CookieStore>,
}

impl HttpClient {
    pub fn new(config: HttpConfig) -> Result<Self>;
    pub async fn get(&self, url: &str) -> Result<HttpResponse>;
    pub async fn post(&self, url: &str, body: &str) -> Result<HttpResponse>;
}

pub struct HttpResponse {
    pub status: u16,
    pub url: String,           // final URL after redirects
    pub headers: HeaderMap,
    pub body: String,
}

pub struct HttpConfig {
    pub timeout: Duration,
    pub user_agent: String,
    pub proxy: Option<ProxyConfig>,
    pub max_redirects: usize,
}
```

Proxy config follows go-stealth pattern: `WEBSHARE_API_KEY` env var.

## 3. Core Browser (`crates/core`)

**Problem:** Need Browser + Page abstractions that tie HTTP and DOM together.

**Design:**

```rust
pub struct Browser {
    http: HttpClient,
    pool: Pool,
    config: BrowserConfig,
}

impl Browser {
    pub async fn new(config: BrowserConfig) -> Result<Self>;
    pub async fn page(&self, url: &str) -> Result<Page>;
    pub fn close(&mut self);
}

pub struct Page {
    pub url: String,
    pub status: u16,
    dom: dom_query::Document,
    session: Session,
}

impl Page {
    // Query
    pub fn select(&self, css: &str) -> dom_query::Selection;
    pub fn select_single(&self, css: &str) -> Option<dom_query::NodeRef>;
    pub fn title(&self) -> String;
    pub fn text(&self) -> String;
    pub fn html(&self) -> String;

    // Forms
    pub fn forms(&self) -> Vec<Form>;
    pub fn form_by_id(&self, id: &str) -> Option<Form>;

    // Navigation
    pub fn links(&self) -> Vec<Link>;
    pub fn meta_tags(&self) -> Vec<MetaTag>;

    // Interaction
    pub async fn navigate(&mut self, url: &str) -> Result<()>;
    pub async fn submit_form(&mut self, form: &Form) -> Result<Page>;
}
```

## 4. Form Handling

**Problem:** Need to extract HTML forms, fill fields, serialize for submission.

**Design:**

```rust
pub struct Form {
    pub action: String,
    pub method: String,       // GET or POST
    pub fields: Vec<FormField>,
}

pub struct FormField {
    pub name: String,
    pub value: String,
    pub field_type: FieldType, // text, hidden, password, select, textarea, etc.
    pub disabled: bool,
}

impl Form {
    pub fn from_element(node: &dom_query::NodeRef) -> Self;
    pub fn set_field(&mut self, name: &str, value: &str);
    pub fn serialize(&self) -> String; // URL-encoded form data
}
```

## 5. Concurrency Pool

**Problem:** Limit concurrent page loads to prevent resource exhaustion.

**Design:** Channel-based semaphore, same pattern as go-browser's `pool.go`.

```rust
pub struct Pool {
    sem: tokio::sync::Semaphore,
    closed: AtomicBool,
}

impl Pool {
    pub fn new(size: usize) -> Self;
    pub async fn acquire(&self) -> Result<PoolGuard>;
    pub fn close(&self);
}
```

## 6. CLI

**Problem:** Need basic command-line interface for testing and standalone use.

**Design:** `clap` with subcommands.

```
ox-browser fetch <url> [--css <selector>] [--text] [--headers]
ox-browser version
```

`fetch` loads a page and outputs HTML (default), selected elements (`--css`),
or plain text (`--text`).
